Codex Local Board｜繁體中文對話進度看板

一、開啟與關閉
請保留完整資料夾，雙擊 Open-Board.cmd。
主要網址：http://127.0.0.1:8787/
重複開啟會沿用本資料夾的服務；Close-Board.cmd 只關閉已核對身分的本看板。
已有其他服務使用相同連接埠時會停止並說明，不會關閉別人的程序。

二、如何看進度
左欄使用 Codex 原始對話名稱，每列一行，可搜尋完整標題。
尚未取得原生名稱的報告放在「其他同步任務」，預設收合。
右側依序查看工作目標、目前工作、下一步、成果、驗收關卡與工作分工。
頁面預設每五秒讀取資料，保留目前選擇與展開狀態。
進度條是已完成且附證據的關卡比例，不是剩餘時間或模型思考。
沒有關卡時顯示待建立；公開摘要、已回報成果及本輪重測結果會分清來源。
對話旁轉圈表示既有 Agent View 已觀測到 Codex 明確執行中；停止時顯示目前未執行。
來源缺少、等待使用者、失效或讀取失敗時顯示未取得執行狀態，不讓舊的轉圈一直轉。
關卡進行中但尚無細部百分比時顯示不定量進度條；只有確認對話執行中才播放動畫。
數字仍是已驗收關卡比例，尚未完成的關卡不靠時間自動加分。
轉圈來源是已運行 Agent View 的唯讀回合狀態，不另外呼叫 AI、不使用 Codex 額度。
未使用這個選配來源時，工作摘要仍可正常顯示；本看板不自動安裝外掛或更改信任。

三、首次整理既有聊天室
看板開啟後，雙擊 Sync-All-Chats.cmd。
它會使用本機已登入 Codex 的可用額度，啟動一次明確同步，整理可取得的公開摘要。
整理結果存入私人 conversation-summaries.json；依視窗結果確認是否成功。
工作中的 Codex 正式回報優先於整理報告，整理報告又優先於純公開文字摘要。
這不會替其他專案重新跑測試；未重測的成果與資料來源必須明示。
看板每五秒刷新只讀本機資料，不會每次呼叫模型。
可先用 sync-all.mjs sync --dry-run 檢查數量，不啟動模型。
每次最多50個尚未直接回報的對話；超限數量列在 omitted_capacity，不代表全部同步。
預設最多等待600秒（10分鐘），可用 --timeout-seconds 指定1至600秒；視窗會顯示階段及已等待時間。
失敗或逾時保留原摘要，但該次可能已使用額度；不自動重試，請勿反覆執行。
私人執行紀錄在 .runtime/sync-runs；不要將這些紀錄或匯出檔上傳。
若手動中斷留下 .runtime/sync-all.lock，先確認已無同步在跑，備份後只移除該鎖再重試。

四、讓工作中的 Codex 自動同步
在本資料夾終端機執行：
  .\runtime\node.exe .\install-agent-guidance.mjs audit
  .\runtime\node.exe .\install-agent-guidance.mjs install --render
確認預覽內容後執行：
  .\runtime\node.exe .\install-agent-guidance.mjs install --apply
它會加入有備份、可移除的全域指導，讓載入指導的 Codex 工作回報短摘要。
既有對話可請 Codex 依公開摘要補齊，需註明來源與未重測內容。
安裝器不強制重啟 Codex，也不更改外掛信任；是否已載入應看實際同步狀態。

查看報告範例：
  .\runtime\node.exe .\agent_report.mjs --example
固定命令已含 --state 時也可加 --example；不會讀寫狀態檔。
請勿把 --example 和 --json-file、--json-stdin 等實際回報參數混用。
來源版若沒有 runtime/node.exe，以上可改用已安裝的 Node。

五、資料與版本
主要看板：Node v2，Open-Board.cmd／Close-Board.cmd，資料 state-v2.json。
舊版相容：Python v1，Start-Board.cmd／Stop-Board.cmd，資料 state.json。
兩個版本使用不同結構。Node v2 不把 source_ready 計入驗收完成。
核心報告使用 Node 18 以上；讀既有 Codex SQLite 索引建議使用內附 Node 24.22.2。

六、進階事件介面
Open-All-Agents.cmd 開啟另附的 Codex Agent View。
它需要原生外掛安裝及信任，並可能產生短效私人查看網址；不要公開該網址。
它的工具事件不等於主要看板的驗收成果。
