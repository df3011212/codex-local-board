Codex Local Board｜繁體中文對話進度看板

一、開啟與關閉
請保留完整資料夾，雙擊 Open-Board.cmd。
主要網址：http://127.0.0.1:8787/
重複開啟會沿用本資料夾的服務；Close-Board.cmd 只關閉已核對身分的本看板。
已有其他服務使用相同連接埠時會停止並說明，不會關閉別人的程序。

手機私人連線（選用）
電腦與手機都安裝 Tailscale，登入同一帳號所屬的私人網路並保持連線。
電腦要開機、保持喚醒，而且看板要持續運行；同 Wi-Fi 或外出行動網路都可使用。
只限 tailnet 存取規則允許的裝置／成員，範圍可能包含其他成員；本工具不代改ACL。
1. 先雙擊 Open-Board.cmd，確認電腦看板正常。
2. 再雙擊 Open-Phone-Board.cmd。
3. 尚未登入或 HTTPS 未設定時，由你本人依 Tailscale 原生視窗完成；本專案不代按授權。
   HTTPS 憑證會公開記錄裝置與 tailnet DNS 名稱，核准前可先檢查名稱。
4. 手機連上 Tailscale 後，在瀏覽器開啟成功視窗顯示的私人 HTTPS 網址，預設使用8443埠。
   手機不能使用電腦的 http://127.0.0.1:8787/ 作為連線網址。
Check-Phone-Board.cmd 只查看狀態，不改設定。
Close-Phone-Board.cmd 只停用本工具持有的手機入口，不關閉本機看板。
重開機後先開本機看板，再開Open-Phone-Board.cmd恢復橋接；Serve設定保留不代表主程式仍在運行。
電腦端檢查成功後，仍需由你在手機實際開啟網址確認連線。
停用時若Tailscale離線，只關閉可驗證的本工具橋接並保留記錄；恢復連線後再執行Close-Phone-Board.cmd完成Serve清理。
主看板仍是127.0.0.1:8787，私人橋接是127.0.0.1:8788，僅提供固定唯讀看板路由。
不提供手機控制Codex、寫入或啟動同步；不啟用Funnel、不修改防火牆、不清除其他Serve設定。
預設連接埠被占用時會停止，不關閉別人的服務。
手機查看和一般刷新不呼叫AI、不另用模型額度；Sync-All-Chats仍須在電腦明確執行且可能用額度。
GitHub Pages只是公開示範，不是你的私人看板入口；私人網址與.runtime資料請勿上傳。
官方安裝：https://tailscale.com/docs/install/windows
官方私人Serve：https://tailscale.com/docs/features/tailscale-serve

二、如何看進度
Codex 對話
左欄使用 Codex 原始對話名稱，每列一行，可搜尋完整標題。
尚未取得原生名稱的報告放在「其他同步任務」，預設收合。
右側依序查看工作目標、目前工作、下一步、成果、驗收關卡與工作分工。
頁面預設每五秒讀取資料，保留目前選擇與展開狀態。
進度條是已完成且附證據的關卡比例，不是剩餘時間或模型思考。
沒有關卡時顯示待建立；公開摘要、已回報成果及本輪重測結果會分清來源。
對話旁轉圈表示既有 Agent View 已觀測到 Codex 明確執行中；停止時顯示目前未執行。
來源缺少、等待使用者、失效或讀取失敗時顯示未取得執行狀態，不讓舊的轉圈一直轉。
關卡進行中但尚無細部百分比時顯示不定量進度條；只有確認對話執行中才播放動畫。
數字仍是已驗收關卡比例，尚未完成的關卡不靠時間自動加分。
轉圈來源是已運行 Agent View 的唯讀回合狀態，不另外呼叫 AI、不使用 Codex 額度。
未使用這個選配來源時，工作摘要仍可正常顯示；本看板不自動安裝外掛或更改信任。

ChatGPT 對話（限同一台電腦開啟本機看板）
在左欄切換 Codex／ChatGPT。已匯入的 ChatGPT 對話會保留原名，可搜尋或篩選封存狀態。
請已登入的桌面 Codex 讀取所需的完整 ChatGPT 對話索引，再依 README 使用 chatgpt-pilot.mjs import 匯入。匯入資料只需對話 ID、名稱及封存狀態。
選一則 ChatGPT 對話，點「用 Codex 自動整理」開啟工作方式視窗。
・只整理架構：查看已有架構，或依對話中明確的專案目標與驗收關卡建立架構。回到看板的 ChatGPT 分頁，在原對話卡片查看架構。Codex 應用程式會保留這則對話，標題加上「[ 回CHATGPT ]」。這次整理不會列在看板的 Codex 工作清單。
・整理架構並實作驗收：指定本機專案資料夾。已有架構就選一個未驗收項目。尚無架構時，Codex 先整理出第一個條件明確且可驗收的項目再開始。這則工作對話的標題會加上「[Chatgpt 轉移 CODEX]」，並列在看板的 Codex 工作清單。
  整理、實作和測試會在同一則 Codex 工作對話進行。缺少實作或驗收條件時，Codex 會先釐清。
兩種方式都要在開啟的桌面 Codex 按送出。建立的架構以原對話名稱存回該則 ChatGPT 的看板卡片。
也可以直接建立或編輯架構、更新手動進度，或開啟原 ChatGPT 對話。私人索引、進度和計畫都留在 .runtime，不要上傳。

在同一台電腦選「整理架構並實作驗收」，Codex 會直接讀取本機看板上的架構。
跨電腦接續時，在 ChatGPT 卡片的專案架構總覽點「下載架構包」，儲存或分享 .codex-plan.json。
接手者在本機看板頁首點「匯入架構包」，選一個未驗收項目和本機專案資料夾，再點「開啟 Codex」，在桌面 Codex 按送出。
接手者可直接用匯入的架構包，無需登入原 ChatGPT 帳號或取得來源對話。驗收結果存到接手者的本機看板。

三、首次整理既有 Codex 聊天室
看板開啟後，雙擊 Sync-All-Chats.cmd。
它會使用本機已登入 Codex 的可用額度，啟動一次明確同步，整理可取得的公開摘要。
整理結果存入私人 conversation-summaries.json；依視窗結果確認是否成功。
工作中的 Codex 正式回報優先於整理報告，整理報告又優先於純公開文字摘要。
這不會替其他專案重新跑測試；未重測的成果與資料來源必須明示。
看板每五秒刷新只讀本機資料，不會每次呼叫模型。
可先用 sync-all.mjs sync --dry-run 檢查數量，不啟動模型。
每次最多50個尚未直接回報的對話；超限數量列在 omitted_capacity，不代表全部同步。
預設最多等待600秒（10分鐘），可用 --timeout-seconds 指定1至600秒；視窗會顯示階段及已等待時間。
失敗或逾時保留原摘要，但該次可能已使用額度；不自動重試，請勿反覆執行。
私人執行紀錄在 .runtime/sync-runs；不要將這些紀錄或匯出檔上傳。
若手動中斷留下 .runtime/sync-all.lock，先確認已無同步在跑，備份後只移除該鎖再重試。

四、讓工作中的 Codex 自動同步
在本資料夾終端機執行：
  .\runtime\node.exe .\install-agent-guidance.mjs audit
  .\runtime\node.exe .\install-agent-guidance.mjs install --render
確認預覽內容後執行：
  .\runtime\node.exe .\install-agent-guidance.mjs install --apply
它會加入有備份、可移除的全域指導，讓載入指導的 Codex 工作回報短摘要。
新指導也要求建立或更新每個聊天室的整體計畫，並在交付時回報建議下一步。
有開發或安裝文件就沿用文件；沒有時由同一個工作Codex建立待確認的初始計畫，不另開模型。
專案架構存在私人 project-plans.json；組織樹可收合、搜尋與只看未完成。
全專案進度和本輪工作關卡分開；完成單次工作不會把整個專案變成100%。
下一步建議可複製回原對話，尚未開始，不會自動替你發送或執行。
Codex輸入框未送出的灰字/草稿不屬於公開工作回報，不會被看板讀取。
平常不需反覆執行Sync-All-Chats；原對話載入指導後會在里程碑回報，畫面約下一次輪詢更新。
既有對話可請 Codex 依公開摘要補齊，需註明來源與未重測內容。
安裝器不強制重啟 Codex，也不更改外掛信任；是否已載入應看實際同步狀態。

查看報告範例：
  .\runtime\node.exe .\agent_report.mjs --example
固定命令已含 --state 時也可加 --example；不會讀寫狀態檔。
請勿把 --example 和 --json-file、--json-stdin 等實際回報參數混用。
來源版若沒有 runtime/node.exe，以上可改用已安裝的 Node。

五、資料與版本
主要看板：Node v2，Open-Board.cmd／Close-Board.cmd，資料 state-v2.json。
舊版相容：Python v1，Start-Board.cmd／Stop-Board.cmd，資料 state.json。
兩個版本使用不同結構。Node v2 不把 source_ready 計入驗收完成。
核心報告使用 Node 18 以上；讀既有 Codex SQLite 索引建議使用內附 Node 24.22.2。

六、進階事件介面
Open-All-Agents.cmd 開啟另附的 Codex Agent View。
它需要原生外掛安裝及信任，並可能產生短效私人查看網址；不要公開該網址。
它的工具事件不等於主要看板的驗收成果。
